# Home menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The home menu that one press of B opens: six functions (timers, tour, surprise, words, settings, close), a line, and 16 example questions that show their multimedia view from a fixed answer, without the AI.

> **Revised 2026-11-15** after the user moved the functions into the menu and dropped the sub-list (spec, "Changed later the same day"). Tasks 1 and 2 were done under the first version; Task 1's names (`try*`) are renamed in Task 3.

**Architecture:**
- **Data and press logic:** a pure header (`try_core.h`), tested on the host.
- **Screen:** `try_list.ino` draws the screen like the trainer's menu and takes over the loop the way the trainer does.
- **Answer:** the code that shows a spoken question's answer moves out of `handleVoiceQuery` into `showAnswer()`, so a fixed answer goes through the same path.

**Tech Stack:** Arduino C++ (ESP32 core 3.3.6, M5Unified), host tests with c++17 + ASan/UBSan.

**Spec:** `docs/superpowers/specs/2026-11-15-home-menu-design.md`

## Global Constraints

- **Branch:** `feature/home-menu` (was `feature/try-questions`) from origin/main. No push without Matthias's go in this session.
- **Labels:** every label, DE and EN, at most 174 px in `fonts/PrimaryFont10pt.h` (the menu font, x 50 to x 224).
- **Nothing that costs money:** no AI call, no text-to-speech, no Wolfram, no `createImage`.
- **Answer texts:** one short line with no facts ("Hier ist Orion." / "Here is Orion.").
- **Language:** labels and answers follow `deviceLanguageIsGerman()`.
- **Night lock:** it applies to a chosen question exactly as to a spoken one.
- **Look:** as `vocabDrawMenu`:
  - 3 rows at y 14 + k × 36;
  - the selected row is a white rounded rectangle 204 × 30 at x 20;
  - the label at x 50 in `getFont12pt()`;
  - a scroll bar at x 230;
  - tabs `HINT_OK, HINT_CANCEL, HINT_NEXT`.
- **Presses**, as the trainer reads them:
  - A = `M5.BtnA.wasClicked()`, then `discardButtonA(0)`;
  - next = `buttonBClicked()`;
  - back = `buttonCClicked()` or `M5.BtnB.wasHold()`.
  - The button module later remaps C on the Plus2 to B twice. Nothing here depends on how.
- **Interface for ai-stick-0a's module:** `void homeMenuOpen()`, `bool homeMenuActive()`, `void openSettings()`.
- **Checks:** `./verify.sh` green for both boards after every task that touches the sketch.

## Review Focus

1. **Display asleep or the stick in light sleep while the list is open.** A press wakes it and redraws the list without acting. Deep sleep closes the list (`saveStateToPreferences`), so no list comes back after a wake.
2. **A timer alert while the list is open.** The alert takes over, and dismissing it redraws the list (the loop's alert block calls `tryListRedraw()`).
3. **No WiFi when choosing.** Wait on the WiFi page as a spoken question does. With no known network, open setup the same way.
4. **A view that can't open** (no memory for the 3D view, source down). `showAnswer` falls back to the text and the Wikipedia picture through `imageQuery`. Every entry has one.
5. **An earlier answer's view still loaded when a question is chosen.** `showAnswer` unloads it (`eduUnloadActive`, `modelViewEnd`) before fetching.
